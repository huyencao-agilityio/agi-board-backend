# agi-board-backend

REST API for AGI Board (Trello-style boards). NestJS 11 and Prisma 7.10 on Cloudflare Workers, D1 (SQLite)
database, R2 for images. Node.js 24 and pnpm 12 for tooling.
Product docs live in the parent `agi-board` repo: `docs/proposal/`, `docs/database/`.
Ticket specs live in this repo: `specs/<card number>/` (`spec.md` from the Trello card via `/pull-ticket`, then
`plan.md`, `tasks.md`). Do not read `../specs/`.
Init plan and decisions: `../docs/backend-init-plan.md`.

## Commands

```bash
pnpm start:dev                  # wrangler dev: http://localhost:8787/api/v1 (local D1 + R2 in .wrangler/)
pnpm lint && pnpm typecheck     # must be clean before a commit
pnpm test                       # unit: src/**/*.spec.ts
pnpm test:e2e                   # e2e: test/*.e2e-spec.ts, against a local D1 in .wrangler/e2e
pnpm db:migrate:new <name>      # empty prisma/migrations/NNNN_<name>.sql; fill it with `pnpm db:diff >> <file>`
pnpm db:migrate                 # apply migrations to the local D1
pnpm db:check                   # fails if prisma/schema has changes with no migration
pnpm db:seed                    # system catalogs (prisma/seed.sql) + preset backgrounds to local R2, idempotent
```

## Rules

- **Scope:** the Trello card, pulled into `specs/<card number>/spec.md`, is the source of truth. Do not add
  features outside it.
- **Layers:** `modules/<feature>/` with module, controller, service, `dto/`, `*.spec.ts`. Services call
  `PrismaService` directly; no repository layer.
- **Auth is global:** `SessionGuard` and `CsrfGuard` run on every route. Mark open routes `@Public()`
  (CSRF still applies to writes). Read the user with `@CurrentUser()`.
- **Permissions:** every board/workspace rule goes in `src/modules/permissions/` as a pure function with a
  row in its table test (risk R-02). System roles (`support`, `super_admin`) never grant access to content.
- **Errors:** throw Nest HTTP exceptions; the global filter returns `{ error: { code, message, details } }`.
  Use 404 (not 403) for content the user may not see, so existence is not leaked. Never reveal whether an
  email has an account.
- **IDs:** UUIDv7 generated by Prisma (`@default(uuid(7))`); never accept ids from the client on create.
- **Real-time events** (Sprint 2+) are sent only after the transaction commits.

## Database (read before touching prisma/)

- Models in `prisma/schema/*.prisma` are the source of truth; `docs/database/schema.sql` is the original design.
- Migrations are plain SQL files in `prisma/migrations/` applied by wrangler (`wrangler d1 migrations apply`);
  Prisma only generates the SQL (`pnpm db:diff`). Deploy applies them before the new code goes live, so keep
  them backward compatible.
- Prisma cannot express CHECK constraints or expression indexes. They are hand-written in
  `prisma/migrations/0001_init.sql` (`-- manual`; CHECKs inline in `CREATE TABLE`, SQLite has no `ADD CONSTRAINT`).
  When adding such an object: write it by hand in the new migration **and** add it to
  `test/schema.e2e-spec.ts`. Always read generated SQL; a SQLite table rebuild must carry the CHECKs over.
- Never use `prisma db push` or edit an applied migration.
- Prisma client is generated to `src/generated/prisma/` (git-ignored, `runtime = "workerd"`). Import from
  `../generated/prisma/client` or `.../enums`.
- D1 limits: no transactions through Prisma (Prisma's D1 adapter runs `$transaction` (both forms) as separate, non-atomic queries; atomic writes use `DB.batch`), no DEFERRABLE
  constraints (swap `card.number` through a temporary value), enums are not enforced by the database, no trigram indexes.

## Gotchas

- Jest runs with `--experimental-vm-modules` (Prisma 7 loads its query compiler via dynamic import);
  use the pnpm scripts, not `npx jest`.
- pnpm 12 blocks dependency build scripts until approved in `pnpm-workspace.yaml` (`allowBuilds`).
- Keep `prisma` and `@prisma/client` on the same exact version; the `latest` npm tag of `prisma` points to an 8.x RC.
- The Worker runs `dist/` (built by `nest build`, which wrangler runs first): esbuild cannot emit decorator
  metadata. Entry `edge/src/index.mjs`; bindings reach Nest through `src/cloudflare.ts`. No Node-only APIs at
  runtime (no fs, no worker_threads: pino has no transport, Swagger has JSON only) and no native addons
  (argon2, bcrypt: use WebAssembly/pure-JS builds). Email goes through a provider's HTTP API, not SMTP.
- Deploy: `.github/workflows/deploy.yml` after CI passes, `develop` → staging, `main` → production.

## Git

- Branches: `main` (releases) ← `develop` (integration) ← `<type>/<kebab-slug>` created from `develop`,
  e.g. `feat/init-structure`, `fix/board-404` (types as in commits, plus `hotfix`, `release`).
  Checked by `scripts/check-branch-name.sh` on `git push` (husky) and in CI.
- PR into `develop`, review required, CI must pass. Never merge a PR or enable auto-merge yourself.
- Commits: Conventional Commits with the Trello ticket id (card number) first in the subject:
  `<type>(<scope>): #<id> <Imperative summary>`, e.g. `feat(boards): #123 Add board route guards`.
  Types: `feat`, `fix`, `chore`, `refactor`, `test`, `docs`, `build`, `ci`, `perf`, `revert`; scope required, lower case.
  Enforced by `commitlint.config.mjs` (husky `commit-msg` hook, and CI on PRs). Ask for the ticket id if unknown;
  never invent one, and never bypass the hook with `--no-verify`.
- PR title: the Trello ticket name, verbatim. PR body: Ticket (link) / What / Why / How tested / Screenshots / Risk
  (`.github/pull_request_template.md`).
