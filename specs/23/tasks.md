# Tasks: #23 Implement feature Create Board

**Input**: `specs/23/` (spec.md, plan.md, research.md, data-model.md, contracts/boards.md, quickstart.md)

**Tests**: required by `.claude/rules/testing.md`: a permission rule needs a table row per case, and a new
endpoint needs an e2e test for the happy path, 401, 404, 400 and 403 `CSRF_INVALID`. All e2e cases go in one new
`describe('create board')` block in `test/home.e2e-spec.ts`. They share one file, so the e2e tasks are not
parallel with each other.

User stories (backend part of the card's Acceptance Criteria):

- **US1 (P1)**: a workspace admin creates a board with a valid name. It is created empty, with the creator as admin
  (AC 1 name validation, AC 2 create and open).
- **US2 (P2)**: the visibility choice is honoured: `workspace` by default, and a `private` board is visible only to
  its members and to workspace admins (AC 3).
- AC 4 (Cancel/`Esc`/outside click) and the dialog UI (spinner, locked fields, tooltips, opening the board) are
  **frontend only**, so there are no backend tasks for them.

Rules every task follows:

- Permission decisions only through `src/modules/permissions/board-access.ts` (no inline role checks).
- The acting user comes from `@CurrentUser()` only. IDs are generated by the server with `uuidv7()`, never taken
  from the body. Map DTO fields explicitly.
- E2E: use the file's helpers `signedIn()`, `write('post', u, path)`, `get()`, `home()`, `makeWorkspace()`,
  `addWorkspaceMember()`, `makeBoard()` and `addBoardMember()`. Assert status, `error.code` and response fields,
  never `message` text.
- PO decisions (2026-11-27): **name capped at 512 characters as an abuse bound**, and **6 default labels** on every new board.

## Phase 3: User Story 1 - Admin creates an empty board (Priority: P1) 🎯 MVP

**Goal**: `POST /api/v1/workspaces/:workspaceId/boards` with `{ name }` creates a `workspace` board and returns 201
with a `BoardTile`. In one atomic batch it writes the board, the creator as board `admin`, 6 empty-name labels and a
`board_created` activity, and no lists (contracts/boards.md).

**Independent Test**: an admin posts `{ "name": "  Roadmap  " }` and gets 201 with `name: "Roadmap"`. The DB then
holds 1 board member (the caller, as admin), 6 labels, 1 `board_created` activity and 0 lists.
